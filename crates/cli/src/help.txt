underdraw — describe a screen once, as JSON, then check it, show it to a
person, and hand it off to web, iOS and Android.

A screen description is a directory holding screen.json (the screen: its
view model, fixtures, conditions and node tree), usually beside tokens.json
and platforms/*.json. The format is docs/format/ in the underdraw repo.

NEEDS
  Nothing to check a description. (Rendering is not built yet.)

START HERE
  underdraw check <dir>      read the description and name every fault

WHAT A COMMAND ANSWERS
  One JSON object on stdout, exit 0. A command that could not do its work
  answers {"error": "…"} with a non-zero exit; the message says what fixes it.
  A description with faults is not an error: `check` answers "ok": false and
  lists them, with exit 0.
  Exceptions: --help and --version print text.

COMMANDS
  For the agent writing a description:
    underdraw check <dir>    every fault, and which fixtures each condition holds in
  For whoever installs underdraw:
    underdraw doctor         what underdraw depends on, and the fix of each finding

RULES TO KNOW FIRST
  - Strings only interpolate: {path} or {path|format}. Every decision is a
    named condition; a choice between values is "cases", ending in "else".
  - No truthiness: a date or a number is not a condition; write != null, > 0.
  - Every condition must be true in one fixture and false in another, so every
    state can be shown. `check` reports one that is not.
  - Loading and error are "phases", trees that read no data.
