WHEN
  After writing or changing a screen description, and before rendering it or
  handing it off. Run it until it answers "ok": true.

WHO
  The agent that writes the description.

READS
  <path>/screen.json, or <path> when it is a file, and kinds.json beside it
  when there is one: every node's kind must be defined there or by
  underdraw, and its looks are checked too (docs/format/kinds.md). Writes
  nothing.

ANSWERS
  {
    "screen":     the screen's name, from "screen"
    "ok":         true when there is no finding
    "fixtures":   the fixtures' names, in the order written
    "phases":     the phases' names (trees rendered before data arrives)
    "conditions": [{"name", "label", "holds_in": [fixture, …]}, …]
                  empty while any finding stands, except a condition that
                  never varies: then the table shows which fixtures to add
    "findings":   [{"at": where — a dotted path or a node id,
                    "problem": what is wrong, and what is allowed instead}, …]
  }

EXIT
  0 when "ok" is true, 1 when there are findings (the answer above is still
  printed in full), 2 when the description could not be read or parsed.

WHAT TRIPS YOU UP
  - A text property (text, title, subtitle, label, detail) always shows text:
    "{booking.total}" there needs |money. Elsewhere a lone placeholder passes
    the value itself.
  - A nullable value may be shown only under a condition that tests it
    != null in its top-level && chain. A negated condition guarantees nothing.
  - A fixture may leave out only fields with a default; T? defaults to null.
  - "$patch" starts a fixture from one written above it.
  - An icon is a Material Symbols name (arrow_back, favorite; .fill for the
    solid form), in a node, a fixture or a look: fonts.google.com/icons.
