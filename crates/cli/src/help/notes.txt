WHEN
  Whenever the person may have said something in the gallery: before each
  round of edits, and after `underdraw check` answers "notes" with any
  waiting. Each note waiting on you is something the person asked for:
  act on it, then answer it. And between rounds, `--wait` in the
  background, to learn the moment the person says something (WAITING,
  below).

WHO
  The agent that writes descriptions. The person starts the notes, in the
  gallery (`underdraw gallery --help`); the agent reads them and answers
  in them.

READS
  notes.json beside each screen.json under <path>: <path> itself, when it
  is a description's directory, or every description under it at any
  depth, as the gallery finds them. A description with no notes.json has no
  notes. A shared component shown on its own, the description
  components/<Name> under its project's root, keeps them in
  components/<Name>/notes.json; what they are on is edited in
  components/<Name>.json, its fixture under "fixtures". Writes nothing, but
  with --answer.

DOES
  A note is a conversation between the person and the agent about a
  design, pinned where it is held, with the same fields ⌘C copies: one
  node of one state they clicked, as the description writes it, with the
  instance they pointed at as context; a region of one state they dragged
  over, its box and the nodes wholly inside it; a whole state; a
  transition, as `transitions` in screen.json writes it; or a navigate, as
  `underdraw check <root>` reports it among its "links", kept by the
  description it is written in. Each is numbered N1, N2… within its
  description, and holds its messages in the order said, each by the
  person or the agent. Only the person starts one. It is never closed:
  who spoke last says where it stands, and that is read from its
  messages, never stored:
    waiting   the person spoke last: for the agent to act on and answer
    answered  the agent spoke last: for the person to read, and say more
              in if they want
  `underdraw notes <path>` lists the waiting ones, each with its whole
  conversation. Edit what it is on in that description's screen.json: the
  node where "node.at" points (the id written there is "node.id", a
  template inside a repeat); for a region, the nodes each of
  "region.nodes" points at, or what belongs in the space its box marks
  when it covers none; the state's fixture or phase; the entry of
  `transitions` the "transition" names; or the navigate on the node
  "navigate.node". A note with "proposes" asks for where acting on its
  node should go: declare the transition, or the navigate, it names. A
  note with "answers" is the person's answer to the assumption on its
  node (ASSUMPTIONS, below). Then answer:

    underdraw notes <dir> --answer N3 --reply "made the price wrap"

  <dir> is that description's directory: <path>/<"description">. The reply
  is at any length, as many lines as it takes, kept as written but for
  blank space at its ends: say what was done, or why not, or ask back.
  It is added to the conversation as the agent's message, and the note is
  answered: its pin turns green in the window. Answering again with the
  same text as the agent's last message changes nothing more; with other
  text, it is one more message.

  A note whose node, region, state or arrow is gone from the description
  (removed or renamed) joins its state's note the next time notes are
  read, so nothing said is lost: its messages go into the note on the
  whole state it was in (a transition's: the state it is from), after a
  line by "underdraw" saying where they were ("on `price`, now gone"),
  and before what the person said there since the agent last spoke. A
  state with no note gets the gone note itself, with the same id; when
  the state is gone too, or for a navigate, the description's first
  fixture's note takes them. Nothing moves while the description has
  findings, and reading again moves nothing twice. The joined note waits
  on the agent while the person spoke last, like any other.

    underdraw notes <dir> --answer N3 --reply "Made the price wrap.
    Should the date wrap too, or be cut?"

ASSUMPTIONS
  The person answers an assumption with a note on its node, its
  "answers" saying which and how: "assumed", the guess as the gallery
  showed it; "guess", what made it: "author" (the node's own `assumed`),
  {"undrawn": [<screen>, …]} (a navigate to a screen not drawn yet) or
  {"component": <component>} (a component underdraw does not know); and "answer":
    right  ✓: the guess was right. Make it a decision: take the guess out
           of the description (remove the node's `assumed`; draw the
           screen; define the component), then answer the note saying so.
    wrong  ✗: the guess was wrong, and the note's messages say what is
           right. Change the description to that, then answer the note,
           as any note.

WAITING
  `underdraw notes <root> --wait` blocks until a note under <root> waits
  on the agent, the person having spoken last in it, then answers as
  `underdraw notes <root>` does, every waiting note listed, and exits 0.
  When one waits already it answers at once; when none does, it reads the
  files again every fraction of a second, and answers as soon as the
  person starts a note, or says more in one, in the gallery. A message of
  the agent's wakes nothing. It keeps nothing between runs: kill it and
  run it again, and no note is lost, for what waits is read from the
  files.

  Keep it running in the background, as a command the agent's harness
  tells it of when it exits (in Claude Code, Bash with run_in_background).
  When it answers: act on each note it lists, answer every one with
  --answer (a reply saying why not, for one you will not act on), then
  start --wait again. A note left waiting makes the next --wait answer at
  once.

    underdraw notes <root> --wait

  It waits as long as it takes; to stop waiting, kill it.

  The agent cannot start a note: `--create` is refused, saying the person
  does that in the gallery. Nothing closes or reopens a note: there is no
  --close, --reopen or --closed. To ask the person something unprompted,
  write an assumption (`assumed`) in the description: the gallery shows
  it, for them to answer; to ask back about what they said, answer in
  their note.

ANSWERS
  {
    "root":     <path>, resolved
    "notes":    the notes waiting on the agent, description by description
                in the tree's
                order, each in the order written:
                [{"description": its directory, relative to root ("." for
                                 root itself),
                  "id":          "N3",
                  "stands":      "waiting" or "answered", read from who
                                 spoke last (DOES, above),
                  what it is on, as one of these:
                  "state":       {"fixture": <name>} or {"phase": <name>},
                                 the state it was written in, with
                  "node":        {"id": the id as written, "at": the JSON
                                 Pointer where it is written in
                                 screen.json, "instance": the element of
                                 each repeat around it, outermost first,
                                 "label": its label or null, "width": the
                                 width it was drawn at}; or with
                  "region":      {"box": {"x", "y", "width", "height"},
                                 in whole points of the picture dragged
                                 on, "width": that picture's width,
                                 "nodes": [{"id", "at", "instance"}, …],
                                 the outermost nodes wholly inside the
                                 box, as "node" names one; [] when it
                                 covers none ("this is too empty")}; or
                  "state" alone: on the whole state; or
                  "transition":  {"from", "on": "<node id>.<event>",
                                 "outcome" (for a call only), "to"}; or
                  "navigate":    {"from": the screen it is in, "node": the
                                 id as written, "to": the screen it names},
                  "messages":    [{"by": "person" or "agent", "says"}, …],
                                 the conversation, in the order said, the
                                 person's first; "says" as many lines as
                                 were written; "by": "underdraw" is the
                                 line saying where the messages after it
                                 were, in a note now gone, and is neither
                                 person's nor agent's
                  "proposes":    null, or, where acting on the node found
                                 nothing declared and the person chose
                                 where it should go: {"on": "<node id as
                                 written>.<event>", "to": <state>}, a
                                 transition to add to "transitions" from
                                 "state", or {"on", "navigate": <screen>},
                                 a navigate to give the node's handler
                  "answers":     for a note answering an assumption only:
                                 {"assumed", "guess", "answer": "right"
                                 or "wrong"} (ASSUMPTIONS, above)
                  "reference":   the same as one line, as ⌘C copies it}, …]
    "waiting":  how many notes wait on the agent
    "answered": how many the agent spoke last in
  }
  With --answer:
  {
    "note":    the note answered, as above
    "changed": false when the agent's last message already said that
  }
  With --wait: the same as without it, once a note waits.
  Exits 2 with {"error"} when <path> is not a directory, --wait is given
  with --answer, the reply is empty, notes.json is not notes as the
  gallery writes them or is in the old form (`underdraw check` says to
  delete it), or --answer names no note there.

WHAT TRIPS YOU UP
  - --answer takes the description's directory, not the root: ids are
    numbered within each description, so two can each have an N1.
  - --wait answers at once while any note waits on you: answer every note
    it lists before you start it again, or it never waits.
  - Quote a reply of many lines as one argument; the shell keeps its line
    breaks.
  - notes.json is the person's: commit it with the description, and never
    edit it by hand.
  - A note is not a fault: `underdraw check` counts the waiting and
    answered ("notes": {"waiting", "answered"}) and exits as it would
    without them. A notes.json in the old form, written before a note
    became a conversation, is a fault: delete it.
